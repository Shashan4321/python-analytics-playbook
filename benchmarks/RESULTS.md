# Benchmark results

Generated by `benchmarks/run_benchmarks.py` on 1,000,000 synthetic order lines.
Machine: Intel64 Family 6 Model 126 Stepping 5, GenuineIntel, Windows 11, Python 3.12.10, pandas 3.0.6, Polars 1.44.2, DuckDB 1.5.5. Median of 3 runs. Your numbers will differ; the ratios are the point.

## 1. Memory: `optimize_dtypes`

## 2. Vectorisation (200,000 rows)

| Task | Slow pattern | Fast pattern | Speed-up |
|---|---:|---:|---:|
| Line revenue | `itertuples` loop: 1.95 s | column maths: 4.7 ms | **415x** |
| Discount band (2-column rule) | `.apply(axis=1)`: 2.41 s | `np.select`: 63.6 ms | **38x** |

## 3. Same KPI, three engines

Net revenue and distinct orders per fiscal year and category. All engines return identical results (checked in `tests/test_performance_and_engines.py`).

| Engine | Time | vs fastest |
|---|---:|---:|
| pandas | 787.9 ms | 6.7x |
| Polars (lazy) | 141.4 ms | 1.2x |
| DuckDB (native table) | 117.6 ms | 1.0x |
| DuckDB (querying the pandas DataFrame) | 2.21 s | 18.8x |

Loading the DataFrame into a DuckDB table once took 1.71 s. Querying a pandas DataFrame directly pays a conversion cost on every query, so for repeated queries load once (or read Parquet) and query the table.
